01 · Concept

Your site is a card catalog

You want projects, experience, a blog and a bookshelf in one place. Most portfolios treat those as unrelated sections with different card styles. A library already has a system that holds all four: the card catalog. Every item gets a typed index card with a call number, subjects and a short description. Drawers become navigation. The blog becomes the reading room.

The metaphor gives the site a recognizable identity without WebGL or heavy animation, so it stays fast and readable. And it gives the bookshelf a reason to exist on a developer site instead of feeling bolted on.

Signature details

  • Nav labels are real Dewey Decimal classes (005 programming, 808 rhetoric, 028 reading, 384 communication).
  • Cards use real catalog-card rules: one red header line, pale blue ruling, and the rod hole punched at the bottom.
  • Dates are violet rubber stamps, each tilted a little differently.
  • Hovering a project lifts its card out of the drawer.
  • Green steel cabinet bands with brass label holders frame the page in both themes.
  • Type: Young Serif for headings, Courier Prime for anything typed on a card, Public Sans for interface text, Newsreader for blog body.

03 · Research

What other developers do

Developer portfolios that get cited as memorable fall into three camps. Immersive sites (3D worlds, heavy motion) are unforgettable but slow and hard to scan. Clean two-column sites are fast and scannable, but one popular layout has been cloned so often it reads as a template. Writing-first sites (digital gardens, now pages) feel personal but often bury projects. The Stacks sits between the last two, with one strong metaphor doing the work an immersive site does with WebGL.

04 · Domain

Is .dev right for a personal site?

Keep anirudh.dev.It's short, it's your first name, it tells people what you do, and you already own it. Add one cheap full-name .com that redirects to it.

Why .dev works

  • The whole .dev TLD is on browsers' HSTS preload list, so every visit is forced to HTTPS from the very first request. Netlify already serves HTTPS, so this costs you nothing.
  • Your audience (recruiters at tech companies, other engineers) reads .dev as "developer" instantly. Google uses it for web.dev, which lends it credibility.
  • First-name domains on .com are almost always taken. anirudh.com is registered.

The trade-offs

  • Outside tech, .dev means little. That matters if you later want the site to represent you beyond engineering.
  • "Anirudh" is a common name, so people searching your full name won't guess anirudh.dev. A full-name .com fixes that.
  • Plain-HTTP tools and redirects break on .dev. That won't affect a site hosted on Netlify.

Headers for netlify.toml

[[headers]]
  for = "/*"
  [headers.values]
    X-Content-Type-Options = "nosniff"
    Referrer-Policy = "strict-origin-when-cross-origin"
    Permissions-Policy = "camera=(), microphone=(), geolocation=()"
    Content-Security-Policy = "default-src 'self'; img-src 'self' data:; style-src 'self' https://fonts.googleapis.com; font-src https://fonts.gstatic.com; frame-ancestors 'none'"

You don't need Strict-Transport-Security: .dev is preloaded, and Netlify already sends it.

06 · Architecture

Two apps, one domain

You want the blog as a separate app tuned for reading. I recommend serving it at anirudh.dev/blog instead of a subdomain. Google says both work, but a subfolder keeps all your links and search history on one site, gives readers one address to remember, and makes analytics simpler. Netlify can proxy a path to another Netlify site, so the blog stays a fully separate app and deploy.

anirudh.dev

Main site

  • Astro, static output, almost no JavaScript
  • Content in the repo: projects.yaml, work.yaml, books.yaml
  • Small interactive pieces only: shelf filter, request slip
  • Netlify Forms for contact, with a honeypot field against spam
anirudh.dev/blog

Reading room

  • Separate Astro app with base: "/blog"
  • Markdown/MDX posts, Shiki code highlighting, RSS feed
  • Generated share images per post, reading time
  • Self-hosted Newsreader font, zero JS by default
shared

Monorepo

  • pnpm workspaces: apps/site, apps/blog, packages/tokens
  • Shared colors, fonts and card styles so both apps match
  • Two Netlify sites from one repo, each with its own base directory

Proxy rule in the main site's netlify.toml

[[redirects]]
  from = "/blog/*"
  to = "https://anirudh-blog.netlify.app/blog/:splat"
  status = 200
  force = true

If you'd rather keep them fully independent, point blog.anirudh.dev at the blog's Netlify site with a CNAME record instead. The designs work either way.

Nice additions

  • A /now page: what you're working on, reading and learning this month.
  • Privacy-friendly analytics (Plausible, Umami or Netlify Analytics) instead of Google Analytics.
  • Optional book sync from Goodreads or Hardcover at build time, so the shelf updates itself.
  • View Transitions between drawers for a card-pulling animation, off when reduced motion is set.
